# Review: Top 100 Claude Code Skills

Reviewed on 2026-10-15. Requirements were rebuilt from `README.md` and the code. Only this file was written.

## How it was checked

- **Data:** parsed `data/skills.js` with Node and checked every entry against the schema in the README. Fetched all 100 `source` URLs (all returned HTTP 200). Fetched each raw `SKILL.md` and compared its front-matter `name` with the entry name (100 of 100 match). Checked every `/plugin install <plugin>@<marketplace>` against that repo's `.claude-plugin/marketplace.json`. Checked the obra/superpowers star count with the GitHub API (299,302, which matches the README's "~299k").
- **Functionality:** drove `file:///.../index.html` in headless Chrome 22 (puppeteer-core). Also checked it through `python3 -m http.server`.
- **Accessibility:** tested keyboard paths by script, ran axe-core 4.10 (WCAG 2.0/2.1/2.2 AA plus best practices) in light and dark mode with the modal closed and open, and calculated non-text contrast by hand from Bootstrap 5.3.8's compiled CSS.
- **Code:** ran `node --check` on both JS files, compared Bootstrap's SRI hashes against the files on the CDN, and looked for dead code, `console.*` calls and TODOs.

## What passed

- **Data:** valid JSON array with exactly 100 entries. Ranks 1–100 are unique and in order. All 13 fields are present with the right types, and there are no extra keys. Every category is one of the 12 allowed values. The longest summary is 145 characters, and each summary is one sentence. There are no duplicate names, sources or summaries. There are no `verified: true` entries with a null source (100 verified, 0 unverified). No fabricated URLs were found.
- **Functionality:** the page renders from `file://` with no console errors from the app. It shows 24 cards and a "Load more (76 remaining)" button. Load more adds 24 cards at a time, moves focus to the first new card, and hides itself at 100. Multi-word search works ("react best" returns 2 results). The category filter works (Security returns 13). Sort A–Z works. The verified-only switch hides an injected unverified test entry. The empty state appears when nothing matches, and its Clear button resets everything and focuses the search box. Copy shows "Copied" and returns to "Copy" after 2 seconds. The theme toggle switches and stays switched after a reload. There is no horizontal scroll at 375px wide.
- **Keyboard:** Tab order is skip link, theme toggle, search, category, sort, switch, then the cards. Enter and Space both open the modal. Esc closes it and returns focus to the card that opened it. The dialog has `role="dialog"` and `aria-modal="true"`.
- **Code:** no framework and no build step. Bootstrap is pinned to 5.3.8 and both SRI hashes match the CDN files. The UI reads only from `window.SKILLS`. Every file has a header comment and each function has a comment. There are no `console.*` calls or TODOs.
- **README:** both ways of running the app work. The add-a-skill example is valid JSON with all 13 fields. It still parses after being added to the array (101 entries), and its `printf` command writes a correct `SKILL.md`. The README's validation one-liner works.

## Findings

| Severity | Area | Finding | Suggested Fix |
| --- | --- | --- | --- |
| Major | Accessibility (contrast) | The "Verified only" switch fails WCAG 1.4.11 non-text contrast (3:1) in both themes. When it is off, it uses Bootstrap's default thumb: `rgba(0,0,0,.25)` on white (about 1.8:1) and `rgba(255,255,255,.25)` on `#212529` (about 2.3:1). Its border is `#dee2e6` on white (about 1.3:1). Users with low vision cannot easily see the control or whether it is on. axe does not catch this because it only checks text contrast. | In `css/styles.css`, override `.form-switch .form-check-input` with a stronger border (for example `border-color: var(--bs-secondary-color)`) and set `--bs-form-switch-bg` to an SVG thumb of at least 3:1 (for example `#6c757d` in light mode and `#adb5bd` in dark mode). Also set `.form-check-input:checked` to `var(--accent)` so the "on" state uses the theme accent. |
| Minor | Accessibility (focus) | Search, the selects and the switch use Bootstrap's built-in focus style: a `#86b7fe` border plus a `rgba(13,110,253,.25)` glow. On white that is about 2.0:1, below 3:1. The `--bs-focus-ring-color` override in `styles.css` does not reach these controls, because Bootstrap compiles those colors into the CSS. So that override does nothing here. | Add `.form-control:focus, .form-select:focus, .form-check-input:focus { border-color: var(--accent); box-shadow: 0 0 0 .25rem rgba(var(--accent-rgb), .5); }`, or give them a solid `outline` like the cards have. |
| Minor | Accessibility (semantics) | Each card is an `<article role="button">`. axe flags this as `aria-allowed-role` (24 nodes per batch). Because `role="button"` hides its children's roles, the `<h2>` card titles do not count as headings, so heading navigation skips all cards. The `aria-label="Rank N"` on a plain `<span>` is also ignored (ARIA 1.2 does not allow `aria-label` on generic elements). | Keep `<article>` with no role. Put the `<h2>` outside any button and make a real `<button>` the trigger: either wrap the title text in it, or use a full-card "stretched" button. Replace the span's `aria-label` with hidden text, for example `<span class="visually-hidden">Rank </span>#3`. |
| Minor | Accessibility (focus trap) | Forward Tab from the last control in the modal (the footer Close button) moves focus out of the page for one stop (`document.activeElement` is `<body>`) before Bootstrap's focus trap brings it back to the × button. Shift+Tab stays inside. This is how Bootstrap 5 works by default, but the README says the modal "traps focus." | Either add a small Tab keydown handler in the modal that wraps from the last focusable element to the first, or change the README wording. |
| Minor | Accessibility (ARIA) | The theme toggle sets `aria-pressed` and also changes its `aria-label` to "Switch to light theme." Screen readers read this as "Switch to light theme, toggle button, pressed," which contradicts itself. | Use one pattern. Either keep a fixed label ("Dark theme") with `aria-pressed`, or keep the changing label and remove `aria-pressed`. |
| Minor | Accessibility (feedback) | After a copy, only the button's `aria-label` changes. Many screen readers do not announce a label change on the button that has focus, so blind users may not hear that the copy worked. | Write "Copied" (or "Copy failed") into a visually hidden `aria-live="polite"` region, for example by reusing a status element inside the modal. |
| Minor | Robustness | `js/app.js` calls `new bootstrap.Modal(...)` before anything renders. If the CDN cannot be reached (offline, blocked network, or an SRI mismatch), this throws a `ReferenceError` and the page shows no cards and no message, even though the data is local. The README says internet is needed, but the failure gives the user no clue. | Check `typeof bootstrap === "undefined"` and show a visible message. Better: still render the cards and only turn off the modal. Or copy Bootstrap 5.3.8 into the project so it works offline. |
| Minor | Data (install steps) | The clone-based installs for #32, #33 and #48–#51 (Vercel) and #88–#91 (Hugging Face) all clone into one fixed folder (`/tmp/agent-skills` or `/tmp/skills`). Installing a second skill from the same repo makes `git clone` fail with "destination path already exists," and a re-run `cp -R` nests the folder inside the existing one. `/tmp` paths also do not work in Windows shells. | Use `[ -d /tmp/agent-skills ] \|\| git clone --depth 1 ... /tmp/agent-skills`, or clone into `"$(mktemp -d)"`. Add `rm -rf ~/.claude/skills/<name>` (or a note) before `cp -R`, and mention that the steps assume a POSIX shell. |
| Minor | Data (source consistency) | For #2 `frontend-design`, `source` points to `anthropics/skills/skills/frontend-design`, but the install step installs `frontend-design@claude-plugins-official`, a separate copy at `anthropics/claude-plugins-official/plugins/frontend-design/skills/frontend-design`. Both exist, but the linked source is not the file that gets installed. The other `anthropics/skills` entries use `example-skills@anthropic-agent-skills`, which does include `frontend-design`. | Change `source` (and `verificationNote`) to the claude-plugins-official path, or change the install steps to the `anthropic-agent-skills` marketplace / `example-skills` plugin like the other entries. |
| Minor | README accuracy | The Files table lists `REVIEW.md` as "Independent review findings and the resolution log." The file did not exist before this review, and it has no resolution log. | Change the description to "Independent review findings," or add a resolution log after the fixes are made. |
| Minor | README accuracy | "Verified: 100 / Unverified: 0" is typed into the README by hand. It will be wrong as soon as someone adds the README's own unverified example. The page itself counts live. | Say the counts describe the data as shipped, or point readers to the live counts on the page. |
| Minor | README accuracy | The JSON check in step 5 of "Add a new skill" uses the relative path `data/skills.js` and needs Node. The README does not say to run it from the project folder or that Node is required. | Add "Run from the project folder (requires Node.js)" to step 5. |
| Minor | Code quality | The `ranking-note` class in `index.html` has no CSS rule. Some overrides in `styles.css` (`--bs-primary`, `--bs-focus-ring-color`) do not affect Bootstrap parts that use compiled colors (for example the checked switch is still `#0d6efd`), so the comment "one accent color" is only partly true. | Remove the unused class, or add a rule for it. Add the component overrides listed in the focus and switch findings above so the accent color really applies everywhere. |

No Blockers found.
